# Инцидент: Entware Dropbear не слушает TCP/222

Дата: 28.11.2026 (MSK; операции MCP 27.11.2026 UTC). Статус: восстановлено, пользователь подтвердил доступ через Termius.

## Причина

На Keenetic Ultra встроенный Dropbear `/usr/sbin/dropbear` слушал TCP/22, а Entware `/opt/sbin/dropbear` не работал. TCP/222 отсутствовал в таблицах слушающих сокетов; локальное подключение возвращало Connection refused. Бинарник и исполняемый `/opt/etc/init.d/S51dropbear` присутствовали. PID-файл `/opt/var/run/dropbear.pid` содержал 662, который принадлежал `/opt/sbin/cron`, а не Dropbear. Скрипт проверял только наличие каталога `/proc/<PID>` и ошибочно сообщал `dropbear already running`. Ветка остановки выполняет kill по PID-файлу: stop/restart в таком состоянии мог бы остановить cron. Причина первоначального завершения Dropbear не установлена.

## Подтверждённое восстановление

1. Проверить PID-файл, идентичность процесса по `/proc/<PID>/exe` и start ticks, наличие Entware Dropbear и слушателей TCP/222. Не полагаться на имя процесса или существование PID.
2. Если PID-файл принадлежит постороннему процессу, Entware Dropbear отсутствует и TCP/222 свободен, с разрешения владельца атомарно переименовать только PID-файл в уникальную резервную копию. Перед переименованием повторно проверить inode, содержимое и идентичность процесса. Не посылать сигнал по старому PID.
3. Выполнить `/opt/etc/init.d/S51dropbear start` один раз. Не использовать stop/restart.
4. Проверить новый PID, `/proc/<PID>/exe` = `/opt/sbin/dropbear`, соответствие inode TCP/222 дескрипторам процесса, получение SSH-баннера с LAN-адреса и сохранение identity/start ticks cron. Проверить вход с клиентского устройства. Если любая проверка не проходит, остановиться и диагностировать; не возвращать устаревший PID-файл поверх нового.

Фактические свидетельства: старый PID 662 принадлежал cron; уникальная резервная копия устаревшего PID-файла; START_EXIT 0; новый PID 15443; IPv4 и IPv6 TCP/222 принадлежат Entware Dropbear; SSH-баннер SSH-2.0-dropbear; CRON_UNCHANGED True. Пользователь подтвердил восстановление доступа. Пароль, VPN, firewall, маршруты и cron не менялись в рамках восстановления.

Идентификаторы внутренних заданий сохранены в приватной библиотеке. Восстановление завершено с exit 0.

## Профилактика (не внедрена)

Подготовить отдельно проверяемое исправление S51dropbear: проверять executable identity и start ticks, PID-файл и его inode, принадлежность слушателя, исключить kill чужого процесса; сериализовать start/stop, безопасно обрабатывать устаревший PID, протестировать повторное использование PID и перезагрузку. Не менять production без согласования. Никаких паролей и ключей в отчёте.
