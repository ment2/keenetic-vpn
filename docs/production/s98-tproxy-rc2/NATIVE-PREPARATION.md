The helper splits activation into `prepare`, `install`, `start`, `verify`; rollback `rollback-stop`, `rollback-restore`, `rollback-verify`. Prepare writes durable verified backups to a new root-only directory, no replacement of active service. Each phase locks existing update lock inode 1280 (never unlinks), checks phase/current boot and exact hashes as appropriate, uses no Xray stop/restart or firewall deletion. Install atomically replaces S98 only and stops a single verified legacy watcher (PID/start ticks/argv/boot, sleep-only child, no other rule writer); old kernel PID reuse race is residual. New watcher start uses readiness handoff. Verify checks state, native read-only guard, DNS via SOCKS hostname resolution and HTTP204/401. Rollback uses original hash and cooperative stop, not arbitrary PID signal; refuses unknown state. Backup/phase files persist across MCP loss; helper intentionally refuses boot/inode drift and requires fresh recovery analysis rather than guessing. Normal cron can apply a new pool between phases; each phase must verify actual state independently. No leak protection disabled.
