## Newly prepared RC36 experiment and independent source audit

Upstream Xray-core 26.2.6 pinned repository commit `12ee51e4bb1d02ece4ef4b7114efa2bcdc130995`. Five exact source Git blob IDs for udpWorker, proxyman/router/stats gRPC and dokodemo must match `git hash-object` before source assertions. Git blob SHA1 is computed on the header `blob <length>` followed by one NUL byte and then file bytes; it must not be confused with raw SHA1 or the compiled MIPS binary SHA256.

Source worker has private `udpWorker.activeConn`, keyed by `connID{src,dest}` (conditionally destination for `!cone`), removes inactive entries on periodic check older than 120s; Xray's actual UDP worker ownership is NOT equivalent to kernel `nf_conntrack` (3s here). Three pinned gRPC services do NOT expose a complete live UDP-worker activeConn inventory API. That does **not** exclude custom instrumentation, nor prove live production ownership readback.

RC36 disposable QEMU guest uses native Xray 26.2.6 MIPS32LE and real Linux4.9 xt_TPROXY to independent backend, preserved source UDP socket, real kernel conntrack entry then expiry with short test-only kernel timeout, and then same UDP socket repeated. Log witness `processing connection from: src:port` must occur **once**, not twice, for the preserved old connection; after expiry host/guest bytes, same process PID/start ticks and no cutover are independently enforced. A successful debug-log count is a bounded observation of reused `proxy.Process`, **not** a complete enumeration of all Xray internal worker entries.

**Verified RC36 results at source SHA `de4f991d9d0a6b2b7ca6f15b6e348518f687fa63`:** [real QEMU and source provenance CI 41243859765](https://github.com/ment2/keenetic-vpn/actions/runs/41243859765) **SUCCESS** (14 focused tests, exact five Git blob hashes verified) and [second independent real packet CI 41243859811](https://github.com/ment2/keenetic-vpn/actions/runs/41243859811) **SUCCESS** (6 source/packet contracts). Both used the actual SHA-pinned MIPS32LE Xray under full-system Linux4.9, original-destination TPROXY, `restrict=on` and separate backend netns. Kernel conntrack entry independently disappeared with 3s test-only timeout while both Xray PID/start-ticks were unchanged, client socket remained open, 26-byte UDP payload echoed before expiry and 36-byte payload echoed after. Actual guest `RC36_GUEST_FIRST_XRAY_UDP_WORKER_PROCESS_ONCE`, followed by `RC36_GUEST_XRAY_INTERNAL_PROCESS_ONCE_BEFORE_AFTER_CONNTRACK_EXPIRY` proves the bounded log-reuse experiment. A full independent internal UDP activeConn inventory **was not exported**, nor was kernel atomic freeze/rollback implemented.

[Full offline CI 41243859759](https://github.com/ment2/keenetic-vpn/actions/runs/41243859759) **SUCCESS 729/729** at the same source SHA, with RC36 Git blob SHA mutation tests. Earlier attempts [41243822678](https://github.com/ment2/keenetic-vpn/actions/runs/41243822678) and [41243822840](https://github.com/ment2/keenetic-vpn/actions/runs/41243822840) **FAILED** when Git blob NUL header was incorrectly encoded in the newly added Python verifier; exact correction is commit `de4f991d9d0a6b2b7ca6f15b6e348518f687fa63`. Do not relabel those failed runs.

A separate disposable advisory-lock counterexample `test_xray_v30_rc36_uncooperative_legacy_flock.py` proves a subprocess that does not participate in a controller's `flock` can still write to a **temporary sandbox file**. This is *not* a live router experiment; it refutes software-only shared locks as evidence of root-descendant fencing.

**Final decision: `HARD_NO_GO_PRODUCTION`**. No complete independently verified legacy Xray internal UDP association inventory including idle+expired conntrack, no mandatory kernel ingress freeze/commit and durable generation CAS, no boot-ID/PID-start-ticks/socket-cookie root descendant enforcement, no physical vendor kernel and independent USB-free boot/rescue acceptance. Every success above is strictly disposable. No verified atomic kernel ingress freeze/commit, original full UDP owner inventory, durable boot/generation CAS, root privileged descendant fence, vendor kernel acceptance, independent USB-free rescue, or full DNS/IPv6 no-leak. Even a green RC36 cannot authorize production.

Forbidden and untouched: Keenetic jobs, production/main/snapshot, Cloudflare, real firewall/routes/cron, merge/deploy/live trial, bypass of any safety boundary.
