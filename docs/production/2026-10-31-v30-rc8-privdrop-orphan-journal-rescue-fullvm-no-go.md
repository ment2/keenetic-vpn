**Date:** 2026-10-31. **Only branch:** `feature/xray-v30-stable-tcp-ingress-lab-20261031`. **Repository:** `ment2/keenetic-vpn`. **Final decision:** FULL-SYSTEM GUEST PASS / PHYSICAL KEENETIC HARD NO-GO.

## Confirmed successful CI, not just authored scripts

- [**Full-system RC8 CI 41220515203**](https://github.com/ment2/keenetic-vpn/actions/runs/41220515203): **SUCCESS**. An actual separate **Linux 6.8.0-147-generic x86_64 guest kernel**, QEMU TCG full-system, **three completely independent two-boot virtual disk scenarios** (`baseline`, `journal-corrupt`, `rescue-corrupt`). Each first VM was deliberately killed with host `SIGKILL` after exactly 2 of 5 archived script replacements and guest `fdatasync(file)` plus `fsync(directory)`. Every second VM booted without the simulated third USB disk. No real router/device was touched.
- **Pre-exec permission confinement**: on every boot a root-owned parent performed eight runs of `fork` followed by **drop to UID/GID 65534 and `PR_SET_NO_NEW_PRIVS` before `exec`**. Each post-exec child used `setsid`, bound localhost TCP+UDP sockets and attempted to migrate into the parent cgroup; the kernel denied the migration and the child remained visible in `cgroup.procs`. This is **eight sequential unprivileged child invocations per guest boot**, not a claim of eight concurrent confined Xray processes.
- **Unowned orphan fail-closed**: an intermediate parent spawned a detached grandchild and exited. The main parent did not have this grandchild as a direct child; it identified the still-present cgroup member and explicitly retained `GUARDIAN_DENIES_RESTART_UNKNOWN_REPARENTED_DESCENDANT`. Only after the orphan voluntarily exited and membership drained did the lab complete. No signal to stale/unowned PID.
- **Baseline reboot**: revalidated SHA256 for all five frozen RC1 originals from the rescue virtual disk; replayed persisted `stage=2` journal and restored 5/5 with a separate next-boot Linux guest. 
- **Corrupt journal reboot**: after host `SIGKILL`, runner first ran offline `e2fsck` on private ext4 disk images to finish pending journal replay; then deliberately replaced the journal with corrupt bytes via offline `debugfs`, and verified the injected bytes by independently dumping them. On second boot, the guest refused rollback **before writing any active scripts**, with `FAIL_CLOSED_CORRUPT_JOURNAL_NO_RESTORATION`. The runner dumped and **byte-compared all five active scripts before/after the second boot** and asserted **zero additional script writes**.
- **Corrupt rescue reboot**: after the same controlled ext4 offline recovery, runner modified one original frozen script in the rescue disk, verified the corruption byte-for-byte, and restarted without simulated USB. The guest refused the mismatched `SHA256SUMS` and **did not modify any of the five active scripts**, independently proven by host `debugfs dump + cmp` for every active file.

Its actual ZIP was downloaded and guest serial logs independently read for all three scenarios: baseline pre-exec+orphan+restore PASS, journal-corrupt pre-exec+orphan+fail-closed PASS, rescue-corrupt pre-exec+orphan+fail-closed PASS.

## New versioned RC8 changes

- `xray/lab/rc8_guest_privdrop.c`: statically linked, **guest-only**. Parent sets safe read-only cgroup traversal rights while preserving root-only writes, enters private cgroup and forks untrusted workers. Each worker **drops UID/GID and sets no_new_privs before executing child program**; post-exec descendants perform actual `setsid`, TCP/UDP listen, attempted cgroup migration (must be denied), and membership check. A separately reparented orphan remains under cgroup observation and blocks restart. This does **not** constrain unrelated pre-existing privileged legacy writers.
- `xray/lab/rc8_fullvm_init`: distinct guest init derived from and separate from RC7. It runs both the original privileged-escape negative experiment and new pre-exec unprivileged scope test before attempting rescue disk mounts. Corrupt rescue SHA256 or `stage=2` journal causes **fail-closed** reboot without restoration.
- `xray/lab/rc8_fullvm_runner.sh`: runs all three modes on **new temporary sparse ext4 images** under disposable GitHub `RUNNER_TEMP`. It replays offline ext4 journal before injection, verifies mutated bytes, boots a second VM without the virtual USB, checks exact serial evidence, compares five active files across negative boots, and asserts HARD NO-GO for physical device.

## Technical safety boundary for Linux 4.9

**Good news, narrow scope:** On the guest **Linux 6.8 x86_64**, dropping arbitrary Unix UID/GID permissions and `PR_SET_NO_NEW_PRIVS` before `exec` prevented the *specific tested unprivileged descendants* from writing to the cgroup parent membership file; this did not require pidfd. It is credible evidence supporting a **least-privilege, parent-owned design**.

**Unsafe extrapolation:** The real Keenetic is historically reported as `4.9-ndm-5`, not guest 6.8. Kernel-specific controller availability, rootless execution, POSIX shell/Entware runtime, cgroup mount permissions, and real Xray packet capture/TCP+UDP **TPROXY `IP_TRANSPARENT` and net capabilities** remain unknown. If Xray requires privileges, the exact minimal **CAP_NET_RAW/CAP_NET_ADMIN** or equivalent needed for listener creation must be validated without giving it capability to migrate between cgroups. The legacy S97/S98/S99/watchdog/cron/wifi/rule writers still run outside any sealed scope and may be privileged; the RC7 root escape remains unmitigated **for them**. Neither a pids cgroup nor a double /proc scan can compensate.

**Boot-rescue boundary:** All disks were virtual sparse images on the same GitHub runner storage. A host `SIGKILL` of QEMU is not an actual electrical power cut and does not validate flash FTL durability. Offline `e2fsck` and corruption via `debugfs` were deliberate fault injection performed on private disk image files, not a physical power-fail process. No compiled, signed and installed physical USB-independent boot guardian exists.
