# RC2 Hysteria2: аудит исходящего UDP и маршрутизации

Дата: 28.11.2026 (MSK). Базовый отчёт: commit `5de97941cb6967bcac842fb1dfef8fadcb830e4b`. SSH-инцидент закрыт: `48df8bbea8b35e766d7886a4c2c38b4ea992f2e0`.

## Контрольный сценарий

Владелец сообщил, что VPN-клиент iPhone подключается к литовскому серверу через Wi-Fi Asus, на котором VPN не установлен. Это независимый пользовательский контроль, но соответствие выбранного профиля именно Hysteria2 и endpoint `lt1.nerpvpn.net:443` ещё нужно подтвердить по экрану клиента без раскрытия учётных данных. Захват на Keenetic при подключении телефона к Asus не показал пакетов; это ожидаемо для трафика, не проходящего через Keenetic. Не трактовать этот результат как отказ сервера.

Предыдущий подтверждённый захват на физическом Keenetic: Xray 26.2.6, по 10 исходящих UDP/443 на каждый из двух HY2 endpoint, 0 входящих; `timeout: no recent network activity`. Пакеты сопоставлены с локальными UDP-портами тестовых процессов; потери захвата ядром 0. Официальный клиент прошёл лабораторию Linux 4.9/MIPSLE, но его физический запуск был заблокирован платформой; повторного запуска или обхода не было.

## Новые результаты

1. Задание `ac603707-600d-49e9-beb6-c8244b91f4a7` завершено с exit 0. Для двух HY2 endpoint маршруты идут через один upstream-шлюз по `apclii0`. Правило для метки TPROXY ведёт в локальную таблицу 100. `mangle/PREROUTING` направляет UDP с домашней сети `br0` в `XRAY_WIFI`. Это не то же самое, что локально инициированный OUTPUT тестового Xray. Политики OUTPUT ACCEPT; найденные цепочки не доказывают отсутствие любой возможной фильтрации, но явного общего запрета UDP не обнаружено. `rp_filter` отключён. Таблица raw не прочитана (exit 3); не утверждать её проверку.
2. Задание `f5e7b8b6-7402-4a74-a678-3da251256dc4` завершено с exit 0. MTU `apclii0` и `br0` 1500, оба интерфейса up. INPUT допускает ESTABLISHED/RELATED. `_NDM_WGOBFS_OUT`, `_NDM_WGOBFS_IN`, `_NDM_ACL_OUT`, `_NDM_OUTPUT` пустые. UDP DNS запрос example.com к upstream-шлюзу получил валидный ответ за 19 мс, к 1.1.1.1 — за 23 мс; RCODE 0, по 2 ответа. Общая двусторонняя работоспособность UDP/53 подтверждена. На момент чтения нет HY2 conntrack записей; это не доказывает отсутствия предыдущих соединений. curl 8.15.0 поддерживает HTTP2, но не HTTP3.
3. Задание `5dcef2e5-0347-4a17-a427-2e29a6fa2ded` завершено с exit 0, `OPENSSL_PRESENT False`: исполняемый openssl не найден в PATH. Независимый публичный QUIC/UDP443 тест этим инструментом не состоялся; не считать его отрицательным результатом сетевого теста. Ничего не установлено.
4. HA read-only recorder job `e87871c7-2f0a-4b5a-8958-814457470f71`, DONE exit 0: RC2 ok, возраст записи 57 с, count 10, complete 10, активные vpn01/vpn06/vpn07/vpn09, active/pending unmatched 0/0.

## Вывод и следующий шаг

Общая недоступность UDP исключена для проверенных DNS-соединений, но специфическая фильтрация UDP/443 или конкретных endpoint, несовместимость установленной сборки Xray (отличается по SHA256 от upstream) и поведение сервера остаются гипотезами. Никаких изменений рабочих VPN, firewall, маршрутов, cron, updater и RC2 в этом этапе. HY2 не допускается в production до физического подтверждения и no-leak acceptance. Не подменять отсутствие входящих пакетов диагнозом ошибки TLS или пароля. Для следующего независимого сравнения требуется подтверждение точного рабочего профиля iPhone: протокол и входной endpoint, без ссылки подписки, пароля или иных секретов. Если профиль совпадает, сравнить его соединение через Asus и Keenetic, отдельно наблюдая br0 и uplink; учитывать перехват прозрачным VPN. Не обходить блокировку запуска официального клиента.
