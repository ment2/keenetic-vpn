## Candidate implementation
- Decode plain/strict base64 response; retain all supported-scheme records; preserve existing VLESS tags/IDs through injected original converter and inventory. Separate hy01/hy02 tags and hy2_ IDs; unsupported Hysteria2 options remain visible, never silently downgraded. Unknown protocol or duplicate identity rejects the generation. Private config and generation digest never published.
- Build native Hysteria2 outbound with TLS verification and optional Salamander. Reject insecure=1, unknown/duplicate parameters, pinSHA256 (mapping still needs separate verification), port hopping, invalid port and invalid encodings rather than silently ignore security-sensitive options. Provider parameter compatibility remains unverified.
- Probe adapter injects existing RC2 probe_node (isolated per-node SOCKS, four independent requests with route witness, no direct fallback by design), cache bound to configuration generation; bounded deadline and cleanup failure propagation. RC2-like sanitized payload carries host, port, protocol, active/pending membership, VPN, HTTP statuses, response durations, exit IP and geo. Actual provider fetch, disk cache, scheduler, MQTT history and dashboard integration are NOT wired into this standalone lab candidate.
- Geo gate requires two fresh matching public exit IP observations with route witnesses and ISO country, coherent timing; RU/BY excluded, mismatch/unknown/stale unverified. Eligibility also requires independent HTTP 204 and OpenAI 401. This is diagnostic eligibility, not permission to alter the active production pool.
