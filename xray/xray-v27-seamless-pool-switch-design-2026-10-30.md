# Keenetic Xray v27 — бесшовное обновление VPN-пулов

Дата: 2026-10-30. Статус: проект, без внедрения.

## Цель
При получении новой подписки проверить новый набор VPN-серверов, безопасно переключать новые соединения на проверенные серверы, максимально сохранять существующие соединения, не допускать прямого fallback через провайдера. Обновление пула не должно само по себе вызывать перезапуск Xray.

## Подтверждённая база
- SOCKS inbound 127.0.0.1:10808, TPROXY inbound 0.0.0.0:12345.
- Outbounds vpn01, vpn02, vpn04, vpn05, vpn06, vpn07, vpn09; blocked blackhole; balancer auto selector ['vpn'], fallbackTag vpn01.
- IPv4 fwmark 0x40000000/0x40000000 -> table 100 -> local default dev lo; iptables XRAY_WIFI TCP/UDP TPROXY -> 12345.
- Текущий startup watchdog указывает на старый watchdog, который может перезапускать Xray при отсутствии SOCKS listener. Это риск для zero-downtime.
- В библиотеке есть отчёты и проекты, но полные исходники генератора подписки, квалификатора серверов и механизма reload пока не подтверждены.

## Требования
1. Сериализация обновлений, поколение (generation id) и журнал переходов; два обновления не могут переключать одновременно.
2. Fetch -> parse -> normalize -> deduplicate -> validate -> health/quality qualification -> candidate pool. Никакой записи в активный config до готовности кандидата.
3. Проверки VPN через отдельный изолированный путь, без изменения активного TPROXY/SOCKS. Проверять OpenAI-qualified по реальным тестам, с TTL и порогами, а не по имени тега.
4. Явный запрет fallback на direct/freedom/provider. При пустом qualified pool оставить старый проверенный пул; если и он недоступен, fail-closed.
5. Сохранять старые соединения, если технически возможно. Сначала исследовать, поддерживает ли конкретный Xray hot-update outbounds/balancer без разрыва; если нет — blue-green с отдельными портами/процессами и управляемой передачей только новых потоков. Никакого утверждения о нулевых обрывах до теста.
6. Предусмотреть drain старого поколения, мониторинг ошибок, rollback на last-known-good, ограничение количества повторных переключений, cooldown/hysteresis.
7. Не менять рабочий Xray, watchdog, cron, маршруты, firewall, kill-switch без отдельного согласования точного плана и команд.

## Критерии приёмки
- Новый пул проверен и переключён без обязательного рестарта активного Xray.
- Нет прямого fallback, TPROXY/SOCKS доступны, Telegram остаётся через VPN.
- Существующие TCP/UDP сессии сохраняются насколько позволяет подтверждённый механизм; измерить фактические разрывы.
- При невалидной/пустой подписке активное поколение остаётся без изменений.
- При ошибке переключения предусмотрен проверенный rollback, не ослабляющий kill-switch.
- Финальные реально развёрнутые версии всех изменённых файлов, SHA256, права, версии, схема установки и отчёт испытаний загружены в /Keenetic/Xray/ после успешного запуска.
