## №2. Бесшовное обновление
Подтверждено:
- staging-only wrapper готовит кандидат и не перезапускает рабочий Xray;
- OpenAI probe проверяет отдельный outbound через временный SOCKS/Xray;
- текущий S97xray использует `killall xray`, а старый watchdog вызывает restart;
- действующий конфиг использует SOCKS 127.0.0.1:10808 и TPROXY :12345.

### Приоритетный путь: Xray gRPC HandlerService (если поддерживается установленной сборкой)
1. Изучить точную версию и доступность API в установленном бинарнике, не меняя конфиг.
2. Проектировать API-inbound только локально с контролем доступа; при отсутствии API — отказаться от этого пути.
3. Назначить серверу устойчивый тег, основанный на канонической конфигурации outbound (без раскрытия секретов), вместо индекса подписки.
4. Сгенерировать candidate и проверить каждый outbound на OpenAI и пригодность для TCP/UDP отдельно.
5. Добавить новые outbound динамически, не удаляя старые; подтвердить наличие и работоспособность.
6. Перевести **только новые соединения** на новый пул. Проверить фактическую семантику маршрутизации и sticky-соединений в Xray; нельзя считать это гарантированным без теста.
7. Старые outbound держать до истечения flow timeout / drain; только затем удалить, если Xray действительно сохраняет существующие соединения.
8. Fail closed: запрет direct/freedom, проверка firewall/killswitch независимо от Xray, rollback к прежнему пулу без restart.
9. Отдельный контроль watchdog: исключить вызов `killall` во время миграции, но только после отдельного согласования и тестов.

### Запасной путь: blue-green
Новый Xray слушает только отдельные локальные порты, без конфликта 10808/12345. Нужен независимый неизменный входной маршрутизатор и conntrack-aware переключение, способное сохранить существующие TCP/UDP потоки. На текущей конфигурации этого нет. Не активировать blue-green без подтверждения такой инфраструктуры.

### Важные ограничения
- Xray HandlerService и hot update пока **не подтверждены**.
- Перенос активного TCP-соединения между процессами не гарантирован.
- UDP session continuity и TPROXY нужно тестировать отдельно.
- HTTP 401 на OpenAI подтверждает достижимость endpoint, но не доступ к конкретной модели.
- Сетевой `leastPing` по Google не равен OpenAI qualification.
