## Independent sender fix

Changed runtime.py and group_runtime.py; original baseline blobs c6a2f6523991b49d3da8847f842144fd549fe0eb and f27c576e7d860d101ab4162ea74d6bb6d40831f1 confirmed against baseline GitHub. Previously group preflight ran before pending retry, so source removal, invalidity or oversize could indefinitely block an already encrypted snapshot. Source preflight now runs only in the no-pending path, under group/state locks. The existing pending ciphertext is verified and sent without reading the current source, subject to resource and integrity checks. New snapshots still require preflight and memory guard. Acknowledgement remains bound to the exact ciphertext hash. Record accepted_spool alongside committed source fingerprint before deleting the accepted spool. After a crash in this cleanup window, delete only a private regular spool whose SHA-256 matches the recorded accepted hash; fsync the containing directory. Unknown/untracked ciphertext is retained, not overwritten, resent, or deleted by guess. Missing/corrupt pending spool is fail-closed. Bounded reads of state/spool use O_NOFOLLOW/O_NONBLOCK, regular file, ownership, private permissions and single-link checks. State root owner checked. Group-level ordinary I/O/preflight errors remain local to the group. No claim of protection against malicious local root or noncooperating writers.

Additional tests cover source oversize, missing/corrupt spool, symlink, mismatched receipt, interrupted pending state commit and interrupted accepted spool cleanup.
