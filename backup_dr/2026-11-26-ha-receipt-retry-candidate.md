## Candidate implementation (offline only)

`ha_receipt_retry.py` separates receipt delivery from claims and operation execution. `deliver_pending` requires monitor lock held by caller and takes existing agent lock nonblocking. It verifies private regular single-link owner files, strict bounded JSON, exact result_ready schema, UUIDs, output/exit-code and payload limits. It checks same journal inode and bytes before every attempt and before unlink. Only an explicit JSON ok=true permits journal removal; directory fsync follows. No token handling, no new job, no owner reconciliation, no policy mutation. Same job ID, lease and output on each submission. Three attempts total, delays 1 and 3 seconds, existing authenticated API callback must use <=20-second network timeout. Recognized transient socket errors, temporary DNS, disconnected response, HTTP 502/503/504 are retried; 429, authentication/policy errors, conflicts, TLS errors, invalid ACK, malformed or uncertain journal stop for manual review. No raw error or journal output is logged by the helper. Exhaustion retains journal. Unexpected I/O failure also stops caller. No unlimited loop; explicit owner review after exhaustion.

`monitor_cycle` is a candidate integration hook: call with monitor.lock held, with original bounded child invocation and existing authenticated result API adapter (only original result endpoint). At startup inspect pending before claim; after failed child inspect pending again. If ready, deliver only and return; next cycle may perform ordinary tick. If no journal and failed child, stop; if claimed_may_have_executed, stop. The existing monitor startup and in-loop pending guards would need to be replaced by this hook, preserving normal public-preflight retry behavior, stop handling, child timeout and fail-closed behavior. The deployed monitor/agent have NOT been modified; this is a tested integration hook, not a fully integrated or deployed monitor release. The wrapper callback must propagate HTTP/transport exceptions, not convert them to a generic error. Real transport deadlines are not certified by the offline callback tests. No HA queue command executed in this iteration.
